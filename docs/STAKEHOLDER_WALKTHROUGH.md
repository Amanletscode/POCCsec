# Stakeholder walkthrough

## Suggested demonstration

1. Open **Project brief** and explain that each page asks for one logical group of information.
2. Use India, Asia/Kolkata, English, 50% allocation, and a September 2026 start date.
3. Open **Team & skills**, request two Consultants, add SQL Proficient plus Python Working, and show the optional manual scoring controls.
4. Run matching and review the role-specific shortlist and visible hard-gate policy.
5. Select an approved person in **Recommendations** and confirm the allocation.
6. Show the new row in the on-screen current-opportunity table and in the `Allocations` sheet of `staffing_register.xlsx`.
7. Open **Capacity & risk** and show the three portfolio views: bench and redeployment, capability coverage risk, and the weekly capacity trend.
8. Ask Copilot: `Find SQL Python Tableau Power BI GenAI people in India with 50-60% availability from 2026-09-21`.
9. Ask Copilot for Germany and show that only Germany work locations are returned, not all of Europe.

## Messages to emphasize

- Grades use governed numeric HR codes.
- Capacity starts from the direct weekly available percentage and is shown as hours using a 42.5-hour PSA week.
- Confirmed output-register allocations reduce the person's free hours in every overlapping week before another match.
- Requested allocation has no hidden tolerance.
- Country and geography expertise are different concepts.
- Historical delivery evidence and low-value confidence/tag fields are not required.
- The current Copilot requires no API key.
- A future approved LLM can interpret language at runtime but cannot change matching rules.
- Specific team is an optional exact gate and never a score.
- Confirmation appends to existing Opportunity and Allocation sheets; repeated clicks cannot duplicate the same employee/opportunity pair.
